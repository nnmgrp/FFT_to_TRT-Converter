Данное руководство объясняет, как интегрировать скомпилированные TensorRT FFT-движки в **chaiNNer**, максимально повысить производительность и избежать потерь скорости при тайлинге.

---

## 1. Автоматическая загрузка плагина в chaiNNer

Благодаря экспорту точки входа `getCreators` в `trt_dft_plugins.dll`, ручная правка файла `load_engine.py` в коде chaiNNer **больше не требуется**!

Чтобы chaiNNer автоматически обнаружил плагин:

### Вариант A: Стандартная папка библиотек TensorRT (Рекомендуется)
Скопируйте `trt_dft_plugins.dll` в директорию библиотек TensorRT внутри встроенного Python-окружения chaiNNer:
```
<папка_chaiNNer>\python\python\Lib\site-packages\tensorrt_libs\
```
Либо в общую системную папку CUDA bin:
```
<CUDA_PATH>\bin\x64\
```
Когда chaiNNer загружает TensorRT, Windows автоматически подгружает все сопутствующие DLL из этих стандартных каталогов.

### Вариант B: Корневой каталог chaiNNer
Скопируйте `trt_dft_plugins.dll` прямо в корневую папку, где расположен исполняемый файл `chaiNNer.exe`:
```
<папка_chaiNNer>\trt_dft_plugins.dll
```

## 2. Анализ проблемы производительности: «Ловушка тайлинга»

При масштабировании изображений высокого разрешения в chaiNNer выбор размера тайла играет решающую роль.

### Почему движок 64x64 может быть медленнее PyTorch

Если движок TensorRT собран со статическим входным разрешением `64x64`:
- Для обработки иллюстрации $2500 \times 2500$ chaiNNer разбивает её на **1 521 фрагмент (тайл)**.
- Каждый фрагмент вызывает отдельный цикл:
  1. Копирование памяти CPU $\to$ GPU через шину PCIe.
  2. Запуск ядра TensorRT (`execute_async_v3`).
  3. Копирование результата GPU $\to$ CPU.
  4. Сшивание швов и наложение масок в оперативной памяти CPU.
- Даже если сам инференс одного тайла на GPU занимает всего $0.5\text{ мс}$, $1521 \times 0.5\text{ мс} = 760\text{ мс}$, а накладные расходы на тысячи пересылок по шине PCIe увеличивают общее время до нескольких секунд. В то же время PyTorch обрабатывает всё изображение за 1 монолитный вызов.

### Решение: Увеличение тайлов и динамические движки

Сборка движков с тайлами большего размера кардинально сокращает количество обращений к GPU:

| Размер входного тайла | Кол-во тайлов для 2500x2500 | Относительное число вызовов | Влияние на общую скорость |
| :---: | :---: | :---: | :---: |
| **64 x 64** | 1 521 | $100\%$ (базовый уровень) | Медленно (упирается в PCIe) |
| **128 x 128** | 380 | $25\%$ (в $4\times$ раза меньше) | в $\sim 3\times$ быстрее |
| **256 x 256** | 95 | $6.25\%$ (в $16\times$ раз меньше) | в $\sim 7\times$ быстрее |
| **512 x 512** | 24 | $1.56\%$ (в $64\times$ раза меньше) | Максимальная скорость |

### Рекомендуемые профили сборки движка

Для видеокарт с **8 ГБ VRAM** (например, RTX 3070, RTX 4060):
- **Статический вариант:** Сборка с параметрами `--height 256 --width 256`.
- **Динамический вариант:**
  ```powershell
  python converter\build_engine.py --onnx model_dynamic.onnx --min-size 64 64 --opt-size 256 256 --max-size 512 512 --workspace 2048
  ```

Для видеокарт с **16+ ГБ VRAM**:
- Динамический профиль с `--max-size 1024 1024` позволяет обрабатывать большинство иллюстраций целиком всего за 1–4 прохода без накладных расходов.
